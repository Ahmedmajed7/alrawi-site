# Al Rawi Smart Home — website

Client: Al Rawi Smart Home (alrawioman.com), Omani smart-home integrator, offices in Muscat and Riyadh.
Bilingual (Arabic default, English) static marketing + product site. Landing = tap-through **film** of a walled villa in an Omani neighbourhood at golden hour, the Hajar range filling the band behind, seen from the far pavement across the street (the key visual, with "SMART LIVING" as HTML top-start; no logo in the scene since 28 Sep 2026, the brand stays in the HTML header) (hero loop → gate → the front door opens → the control panel on the first wall on the right → four more devices → the living room, where a phone comes up and the visitor runs the curtains and the lights from it → backwards out of the door, which closes in front of the lens onto the smart lock), plain `<video>` so it is smooth on old PCs. The per-product 3D viewer was removed at the client's request (29 Sep 2026); product pages show photos. Goal set by the client (28 Sep 2026): photoreal, never "graphic or plastic"; each device's specs open as an Iron Man-style holographic HUD. Placeholder clips are recorded from the 3D villa; the final clips are AI video (see `docs/film.md`). Design: luxury light cinematic (paper/stone/brass; type Marcellus + Jost, Arabic El Messiri + Cairo, all via `--f-*` tokens). No backend.

## Stack
- Astro 7 (static output, `trailingSlash: 'always'`), vanilla CSS with tokens (`src/styles/01-tokens.css`), self-hosted fonts (Marcellus, Jost, El Messiri, Cairo via @fontsource).
- Film player `src/scripts/film/player.ts` driven by `src/data/film.json` (written by `npm run film:encode`). The three.js walkthrough in `src/scripts/three/house/` (live with `?live3d`; used to record the film) (walkthrough.ts orchestrates; loader/materials/renderer/environment/street/vegetation/door/court/interior (+ interior-*.ts)/camera-rig/devices/slideshow/author; `court.ts` rebuilds the entrance court in clean geometry where the AI shell was cut away: `villa.json` `court-*` cuts) driven by `src/data/house.json` (poses, stops) and `src/data/villa.json` (model cuts + floor plan); product viewer `src/scripts/three/product-viewer.ts`; procedural device models `src/scripts/three/procedural/index.ts`; GSAP; Lenis (desktop only).
- Deploy: Cloudflare Pages, output `dist/`. Headers in `public/_headers`.

## Commands
- `npm run dev` / `npm run build` / `npm run preview` / `npm run check`

- `python3 scripts/make-webp.py` — convert hand-picked catalogue images into `public/img/`
- `npm run fetch-nalite` — download supplier gallery photos listed in `products.json` `sourceImages`

- `npm run sky:build` — bake the Poly Haven golden-hour sky HDRI (`evening_road_01_puresky`; `--preview --src=<id>` bakes a candidate into `dist/` and prints the `?skyimg=…` flags to try it live) into `public/textures/sky/sky-<hash>.webp` and set `house.json` `sky.image`, `skyYaw`, `sun.dir` (`--src=`, `--azimuth=`)
- `node scripts/build-env-textures.mjs` — convert the cached Poly Haven exterior sets (render wall, dense sand, lawn AO/roughness) into `public/textures/env/`
- `node scripts/fetch-interior-textures.mjs` — download the interior PBR sets (linen, velvet, walnut veneer, limewash plaster; Poly Haven CC0) into `public/textures/interior/`
- `npm run trees:build` — simplify + compress the photoscanned sidr tree into `public/models/tree-<hash>.glb` and set `house.json` `plants`
- `node scripts/build-props.mjs [--only=kind,…] [--wire]` — photoscanned Poly Haven props (shrubs, potted plants, planters, armchair, coffee table, vases, street lamps) → `public/models/prop-<kind>-<hash>.glb`; `--wire` writes `house.json` `props` (the scene falls back to code-built pieces for any missing kind)
- `npm run film:record` — record the 3D walkthrough frame-exact into `assets/film/source/` + keyframes (needs `npm run dev`; `SITE=` to point at it; `--check` prints a motion/jerk metric per clip and PASS/FAIL (a FAIL is usually a repeated frame: look at the frame it names), `--only=` (clip ids, and `app-scene`: the living room in every state the phone can put it in, 121 drape positions × lights on/off × the bounce light baked for parted and for drawn drapes, which the encoder blends by position; about 40 minutes; it resumes where it stopped), `--size=`, `--blur=K` motion blur for the moves (6 at 60 fps; recording takes about K times longer), `--fps=` / `--hero-fps=` (defaults 60 / 30); `--size=2560x1440` records the 2K film the top rung is cut from (the page renders at `?pr=1.5`, the same 3840-wide buffer 1080p is averaged down from); the recorder replaces a browser that stalls and carries on from the frames on disk (`--resume` keeps them across runs, `--frames=a-b` draws those frames of one clip again), and draws again any frame that repeats the one before or comes out black; record one `--only=<clip>` per process under `caffeinate`, against a frozen copy of `dist/` on its own port so the working tree can go on changing, and let nothing else touch the GPU meanwhile: two record renders at once can come back solid magenta, and even a headless screenshot of the film player cost the recorder a repeated frame (2 Oct 2026; take QA screenshots with `--disable-gpu` until it is done))
- `npm run terrain:build` — the real Hajar behind the villa from AWS Terrain Tiles (house.json `terrain` viewpoint; `--preview --cands="lat,lon,bearing;…"` compares viewpoints) → `public/models/terrain-<hash>.bin` (+ lite); re-run after `sky:build`
- `npm run serve` — serve `dist/` like Cloudflare Pages (`_headers`, brotli, ranges) on :4331; judge load speed there, not on `astro preview`
- `npm run film:encode` — encode `assets/film/clips/<id>` (AI) or the placeholders to `public/film/`, write `src/data/film.json`, posters and `og.jpg` It first builds a master per clip in `scripts/_cache/film-master/` (27 Sep): `assets/film/steady.json` boxes held with a temporal median (z-fighting faces), time resampled with an even shutter at `assets/film/speed.json` speeds (multiples of 0.25; now all 1: the rig plans every move at its final pace; a move recorded with `--blur` at speed 1 is kept frame for frame, blending on top of real motion blur doubles edges), deflicker + temporal denoise, then the grade (`LOOK`: clarity, deeper mids, sharpen); CRF 19, the hero as one GOP. The app stop's room states are published as one stacked video per rung (lights on over lights off, drapes there and back; film.json `scene`) plus four corner stills. Output is a ladder per clip (film.json `rungs`): 720p / 1080p / 1440p in H.264 + HEVC (2K is the top at the client's request; each file kept under Pages' 25 MB), only rungs the source is tall enough for; the player (`chooseRung` in `film/player.ts`) picks the rung that fills the screen's device pixels, capped for phones (1080p), low memory/CPU/slow lines, confirmed with `navigator.mediaCapabilities` (smooth, and power-efficient above 1080p), steps down for the moves when the hero's measured download says the line is slower, and for the rest of the visit if a clip drops > 8 % of its frames. See docs/film.md "Published look". The recorder renders without grain or lens fringing.
- `node scripts/build-oman-map.mjs` — the projects map's shapes: Oman's governorates from Natural Earth admin-1 (cached in `scripts/_cache/geo/`), dissolved into the profile's nine regions → `src/data/oman-map.json` (paths + where each region's light stands; `AT` in the script overrides a position)
- `python3 scripts/extract-profile.py [profile.pdf]` — the photographs taken from the company profile → `public/img/profile/` (needs pypdf + Pillow): the four "Smart & Easy Control" cards (page 16), one photo per service (`service-<slug>.webp`, `services.json` `image`) and the photo beside the CEO's message; crops in `SHOTS`
- `npm run shoot:stops` — stills of the live 3D (only used by `?live3d`'s no-WebGL fallback)
- `node scripts/shoot.mjs out.png URL [w h] [waitMs] [selector] [jsBefore]` — headless screenshot; walkthrough dev flags (all switch the landing to live 3D): `?live3d`, `?stop=N`, `?cam=x,y,z&look=x,y,z[&inside=1]`, `?clip=<y>`/`?cx=`/`?cz=` (cutaways), `?hide=shell,interior,door,gate,env`, `?env=sky,mountains,street,grass,trees,oasis,apron,logo,clouds,birds` (skip), `?model=/models/villa-dev.glb`, `?ray=x,y,z,tx,ty,tz;…`, `?author`, `?tier=low|high|off`, `?slides=1`, `?lights=0…1` (the rooms' own lights, build time), `?bake=0…1` (where the west drapes stand while the bounce light is baked), `?record` (film-quality renderer at 2x: 4K sun shadows with the villa's PCSS filter on fixed taps, 32-sample AO, depth of field; `?nodof` turns the lens off, `?nograde` the grade; when shooting stills with `?record` run `window.__rec.begin()` as the jsBefore so the frame renders)

- Camera (`house/camera-rig.ts`): every move is planned in full the moment it starts (`planMove`, pure: the offline simulator runs the same code). Body: a centripetal Catmull-Rom through the via points, resampled by arc length and smoothed, paced by a minimum-jerk profile over a cruise-speed field (`PACE`: 3.7 m/s indoors, 2.9 through the front door and the cased opening, 11 over the lawn; `RAMP` 0.75 s in, 0.95 s out). Head: a planned yaw/pitch track through the start pose, optional `aims` and the final look, tied to the body's progress, so both start and stop on the same frame exactly on the authored pose (no spring, no lag, no settle). `LIMITS` stretch a move until yaw ≤ 70°/s and 140°/s², pitch ≤ 45°/s and 100°/s², acceleration ≤ 8 m/s². `tourMoves()` builds the tour from house.json: enter (street → gate → door → the panel), goTo (stop to stop; back = the same path reversed), leave (from the living room backwards out of the front door; the lens comes to rest, then the door closes in front of it onto the lock), reenter, outro. The tour takes about 32 s. Keep via points ≥ 0.5 m from surfaces and at eye level indoors (2.05 m absolute).

## Conventions
- RTL first: logical CSS properties only; `.icon-dir` mirrors directional icons under `[dir=rtl]`.
- Every text shown to users comes from `i18n/*.json` or the bilingual data files, never hard-coded in components (except the 404 page).
- `[data-reveal]` for scroll reveals; `data-stagger` on the parent staggers children.
- Performance tiers (`perfTier()` in `three/common.ts`): `off` shows photo/poster, `low` disables bloom/shadows/grass/transmission, `high` gets everything.
- The whole hero is tappable (only `a`/`button` catch the pointer).
- `/film/*` and `/models/*` are cached immutable: published files always carry a content hash.
